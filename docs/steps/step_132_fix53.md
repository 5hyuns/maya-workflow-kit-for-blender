# Step 132 lane fix53 — Tool Settings open / close narrows the viewport at UI scale 1.25 (#53)

## 계획

증상 (#53): Windows 125 % (유효 UI 배율 1.25) 에서 새 Maya 장면 → Windows > General Editors > Tool Settings 두 번 (열기 · 닫기)
→ 메인 뷰포트 963 → 918 px. `--ui-scale 0.8` (유효 1.0) 에서는 통과.

### 측정 (`tmp/probe53/gui_probe53.py`, 1600 × 900 창, 로드 → 열기 → 닫기 영역 표)

| 배율 | 로드 직후 | 열린 뒤 | 닫힌 뒤 |
|---|---|---|---|
| 1.0 | 툴 박스 90 · 아웃라이너 93+260 · 뷰 356+963 · 셸프 64 | 툴 박스 **56** · 아웃라이너 59+294 · 독 356+278 · 뷰 637+682 | 뷰 356+**963** (툴 박스 56) |
| 1.25 | 툴 박스 90 · 아웃라이너 93+260 · 뷰 356+963 · 셸프 56 | 툴 박스 **70** · 아웃라이너 73+**325** · 셸프 **80** · 독 401+290 · 뷰 694+625 | 뷰 401+**918** |
| 1.5 | 툴 박스 89 · 아웃라이너 94+258 · 뷰 357+961 · 셸프 46 | 툴 박스 **84** · 셸프 **96** · 독 357+333 | 뷰 357+961 |

- 킷의 맞춤을 끈 실행 (`PROBE_NOFIT=1`: `toolbox.fit_columns` 무력화): 1.25 에서 열기 · 닫기 전후 영역이 **픽셀까지 같다**
  (뷰 356+963 → 356+963). Blender 자신은 분할 때 레이아웃을 다시 맞추지 않는다 — 이슈의 추정 원인 ("Blender 최소 크기로 재맞춤") 은 틀림.
- 로드 때 맞춤이 끝난 실행 (`ALLSET_FIT_WARP=1`, 실제 세션과 같음): 1.25 에서 뷰 918 → 열기 · 닫기 → 918, 정확히 돌아온다.

**원인**: `ui/toolbox.fit_columns` (0.5 s 타이머) 는 툴 박스 열 = 56 × 배율, 셸프 행 = 64 × 배율, 아웃라이너 = 260 × 배율을 계속
강제한다. `screen.area_move` 는 `screen.active_region` 이 None 일 때만 poll 이 통과하므로 (step 99) 이동은 보류되다가, **poll 이 처음
통과하는 순간** 에 실행된다. 이벤트 시뮬레이션 세션 (커서 워프 꺼짐) 에서는 그 순간이 독 분할 직후 (분할이 active_region 을 비움)
였다: 툴 박스 90 → 70, 그 다음 틱에 아웃라이너 오른쪽 모서리가 +45 px (280 → 325) — 이미 그 오른쪽에 있던 독을 밀고, 독이 닫히면
그 폭이 뷰포트에서 빠진다 (963 − 45 = 918). 1.0 에서는 아웃라이너 맞춤이 측정 시점까지 오지 않아, 1.5 에서는 셸프만 움직여 뷰 폭이
그대로였다.

실제 세션에서도 같은 구조의 문제가 남는다: 로드 때 워프 맞춤이 실패하면 (마우스를 움직임, MAX_WARPS 소진) 보류된 이동이 아무 때나 —
사용자가 영역을 나누거나 모서리를 끌려고 틈에 마우스를 올린 순간 — 실행되고, 맞춤이 끝난 뒤에도 사용자가 끈 아웃라이너 폭 · 셸프 높이를
틈에 마우스가 갈 때마다 되돌린다.

### 고침 (delegated)

맞춤은 **로드된 (또는 UI 배율이 바뀐) 레이아웃을 그대로일 때만** 한다:

- 화면마다 상태 `(ui_scale, 영역 포인터 집합, armed)`. 처음 보는 화면 · 파일 로드 · UI 배율 변경 → armed (그 순간의 영역 집합 기억).
- 영역 집합이 바뀌면 (분할 · 닫기 · 독 · 떼어내기 — 사용자든 킷이든) 그 화면은 disarm, 같은 배율 동안 다시 맞추지 않는다 (독을 닫아
  집합이 원래대로 돌아와도 다시 arm 하지 않는다: 닫은 직후 맞춤이 끼어드는 것도 같은 버그).
- 맞출 것이 없어지면 (이동도 보류도 없음) disarm: 맞춘 뒤 사용자가 모서리를 끌어도 되돌리지 않는다.
- 툴 박스 `settle` 과 열이 좁을 때 메인 뷰 툴바 대체 (`_fallback`) 는 armed 와 상관없이 계속 (영역 이동이 아님).

버린 대안: (1) startup.blend 를 1.6 까지 맞는 크기로 저장 — 영역 크기는 UI 배율을 따르지 않아 한 크기가 모든 배율에 맞을 수 없다
(툴 박스 56 × s, 셸프 64 × s, 아웃라이너 260 × s). (2) 로드 때 결정적으로 맞추기 — Python 은 `screen.active_region` 을 비울 수 없어
워프 없이 `area_move` poll 을 통과시킬 방법이 없다. (3) 독 열기 · 닫기가 폭을 저장 · 복원 — 증상만 막고 다른 분할 · 모서리 끌기에서는
그대로.

검증: `gui_step106_tool_settings` 1.25 / 0.8 통과, `step5_layout`, `step49`, `step99_first_screen` (워프 맞춤), `step112`, `step116`
GUI, 헤드리스 `step132,step49,step99,enable_disable,step130`. 1.25 의 로드 · 열림 · 닫힘 스크린숏 비교.

## 한 것

- `src/allset/ui/toolbox.py`: `_state` (화면 이름 → [UI 배율, 영역 포인터 집합, armed]), `_armed` / `_disarm`; `fit_columns` 는 armed 인
  화면만 셸프 행 · 툴 박스 열 · 아웃라이너 모서리를 옮기고, 옮길 것이 없으면 disarm. `settle` · 메인 뷰 툴바 대체는 그대로.
- 측정하며 하나 더 고침: 처음에는 "처음 본 화면" 을 0.5 s 타이머에서 arm 했는데, 테스트의 독 분할 (로드 0.39 s 뒤) 이 그보다 먼저 와서
  분할 뒤 8 영역이 기준이 됐다 (`load_post` 가 등록한 0 s 타이머도 그 사이에 돌지 않았다, 측정). 그래서 `_fit_after_load` (load_post) 가
  그 자리에서 모든 창의 화면을 로드된 영역 집합으로 arm 한다.
