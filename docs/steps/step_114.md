# Step 114 — Distribution prep 2: extension guideline violations

Audit `docs/distribution/extensions_audit.md` (copy of `hermes/autodrive_bmk/extensions_audit_1019.md`): two violations
of the add-on guidelines / Terms of Service.

## 계획 (delegated)

1. **`sys.modules` 삽입** (`command_line/__init__.py` `install_maya_module` put a stand-in `maya` / `maya.cmds` in
   the global module dictionary while the kit was enabled — guideline: no `sys.modules` / `sys.path` changes).
   The cmds shim only has to work in code the kit itself runs: the Command Line, shelf buttons and the Script Editor
   all execute in `command_line/runner.namespace()`. That namespace gets its own `__builtins__` whose `__import__`
   (`runner._import`) answers `maya` / `maya.cmds` with a stand-in package object that is never registered; every
   other import and a real `maya` (mayapy installed) go to Python's import. Functions defined there keep working
   because their globals carry the same `__builtins__`.
2. **Asset licence**: list every non-code file in the package, check they are all kit-made, declare them CC0
   (Terms 1.2). The manifest `license` list takes `SPDX:CC0-1.0` next to `SPDX:GPL-3.0-or-later` (checked with
   `blender --command extension validate`), plus `ASSETS_LICENSE.txt` in the package naming each file and its
   generator, and a README line.
3. **Legacy `bl_info`** out of the extension build (guideline recommendation): the source `__init__.py` has none;
   `tools/build.py` appends a `bl_info` built from the manifest only when writing the legacy zip.
4. While at release_check: its sidebar tab check (FAIL since step 99) uses the dock's own switch.

## 한 것

- `command_line/runner.py`: `_import` / `_builtins` / `_maya` — `import maya.cmds as cmds`, `from maya import cmds`,
  `import maya.cmds`, `from maya.cmds import ls` work in the namespace; nothing enters `sys.modules`.
  `command_line/__init__.py`: `install_maya_module` / `uninstall_maya_module` removed (and `sys` / `types` imports).
  Shelf buttons copy the namespace (`dict(runner.namespace(), ...)`), so they inherit the hook.
- Assets in the package (all generated by the kit's own scripts): `app_template/Allset/splash.png`, `splash_2x.png`,
  `welcome.png` (`tools/make_splash.py`), `app_template/Allset/startup.blend` (`tools/make_startup.py`),
  `theme/studio_grey.xml` (`tools/make_theme.py`). UI icons are drawn by code at run time (no files). No Autodesk
  asset. `src/allset/ASSETS_LICENSE.txt` (CC0-1.0 list), manifest `license = ["SPDX:GPL-3.0-or-later",
  "SPDX:CC0-1.0"]`, README (Korean + English licence sections).
- `src/allset/__init__.py`: no `bl_info`; `tools/build.py` `legacy_bl_info()` (name / version / Blender / tagline
  from the manifest) appended to `allset/__init__.py` in `dist/allset-<ver>-legacy.zip` only.
- `tools/release_shots.py`: tab check sets `WindowManager.allset_dock` instead of Ctrl+wheel (three dock tabs since
  step 99: the wheel went past the Channel Box onto Blender's C "Item" tab).
- Tests: `tests/test_step114_guidelines.py` (4: enable / run every import form / shelf-style namespace copy /
  disable leave `sys.modules` without `maya*` and `sys.path` unchanged, `import maya.cmds` fails outside; no
  `sys.modules[...] =` / `sys.path.insert` in the source; asset list = the five kit files, all in
  `ASSETS_LICENSE.txt`, manifest licences; extension zip without `bl_info`, legacy metadata from the manifest).
  `test_step7_top_ui.test_import_maya_cmds` checks the four import forms and no `sys.modules` entry (the old
  "removed on disable" test went with the global entry); `test_step61_distribution` expects both licences.
