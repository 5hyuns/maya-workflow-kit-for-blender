## 사용자 인터뷰 답변 (가장 강한 증거: 본인이 P1)
1. 회사 밖에서 Blender로 끝낸 작업: **모델링, 텍스처(UV), 리깅, 웨이트, 디폼**. 실시간 렌더(게임) 위주라 오프라인 렌더는 거의 안 함. 그래도 Blender 렌더는 잘 되어 있다고 느낌.
2. Maya 경력: **모델링과 애니메이션 비중이 비슷함**.
3. 회사(Maya)↔개인(Blender) 파일 왕복: **거의 없음.** 이유: Maya와 Blender가 너무 달라서 **키·조작에 시간이 너무 많이 들어서**.
4. 외부 애니메이터 테스트: 어렵다, **본인 테스트만**.
5. 순서 결정: **설문보다 우리가 정한다.**

## 답변이 바꾼 것
- **파일 왕복은 원인이 아니라 결과였다.** 파일이 안 오간 이유는 손·조작 비용 때문이다. → "두 집 살림 = 파일 왕복 1순위"(3차 잠정안)는 내려간다. 손이 해결돼야 왕복도 생긴다.
- **실제 경로는 "에셋 하나를 끝까지"였다.** 모델 → UV → 리그 → 웨이트 → 디폼 → (애니) → 엔진. 모델러냐 애니메이터냐로 나누는 것보다, **실시간(게임) 캐릭터·에셋 파이프라인 하나**가 본인의 실제 작업이고, GitHub에서 반응한 사람(TA·파이프라인 TD 다수)과도 맞는다.
- **렌더는 Blender 장점으로 남겨 두고 투자하지 않는다.** 실시간 위주 대상에게는 엔진으로 내보내기가 렌더보다 중요하다.
- **"첫 1시간" 대신 "에셋 하나를 끝까지"를 기준으로 쓴다.** 경로 하나라 애매하지 않고, 본인이 직접 테스트할 수 있다.

## 정체성 (제안)
**"Maya 손으로 Blender에서 실시간용 에셋을 끝까지 만든다."**
모델링 → UV → 리깅 → 스킨 웨이트 → 디포머 → 애니메이션 → 게임 엔진 내보내기까지, 각 단계가 Maya 손으로 막힘없이 이어진다. 렌더·시뮬레이션은 Blender 그대로 쓰도록 안내만 한다.
태그라인 "The whole Maya workflow in Blender"의 **whole = 에셋 하나를 처음부터 엔진까지 Maya 손으로**.

| 순서 | 영역 | 이유 | 깊이 |
|---|---|---|---|
| 0 | 손 (내비게이션·선택·핫박스·Channel Box·홀드 키) | 모든 단계의 바닥, 외부 버그 보고가 여기 | 버그는 늘 최우선 |
| 1 | 모델링 + UV | 본인 경로 1단계, 현재 사용자 반응(모델러·TA) | 손 감각 버그 + 빠진 핵심 툴 |
| 2 | 리깅 + 스킨 웨이트 + 디포머 | 본인 경로 핵심, Maya TA 강점, Blender와 차이가 가장 큰 곳(웨이트 페인트·컴포넌트 에디터·조인트 방향) | 깊게 투자 |

| (참고) | Maya ↔ Blender 파일 왕복 | 손이 해결된 뒤 생기는 수요 | 3번 안에서 FBX 축·스케일만 같이 |

## 측정
- **에셋 하나 끝까지(Maya 손)**: 기준 에셋 2개(하드서피스 프롭 1, 캐릭터 1)를 모델 → UV → 리그 → 웨이트 → 디폼 → 간단한 애니 → 엔진 FBX까지. 에이전트 자동 측정 + 사용자 본인 녹화 1회. 지표 = 막힘(BLOCKED) 수, 어색함(AWKWARD) 수, 블렌더 키로 빠져나가야 했던 횟수.
- 릴리스 후 14일 다운로드, 외부 이슈 수(참고).
