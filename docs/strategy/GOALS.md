# Maya Workflow Kit — 목표 정의 (2026-10-26, 사용자 결정 반영 초안)

근거: STRATEGY.md · RESEARCH.md · UNKNOWNS.md (같은 폴더). 이 문서는 "무엇을 만들 것인가"가 아니라 "무엇을 이루려는가"만 정한다.

## 1. 미션 (왜 존재하는가)
Maya로 일을 배운 사람이 **다시 배우지 않고** Blender로 작업할 수 있게 한다.
손은 Maya 그대로, 결과물은 Blender의 장점(무료, 빠른 렌더, 모델링 도구)으로 얻는다. 언제든 순수 Blender로 돌아갈 수 있다.

## 2. 누구를 위한가 (결정됨: P1+P2)
- **P1** Maya 10–20년 경력자. 개인 작업·부업을 Blender로 하고 싶지만 손이 Maya라서 못 옮기는 사람.
- **P2** 회사는 Maya, 개인·프리랜스는 Blender. 두 프로그램을 오가는 사람.
- 대상 아님: Blender를 처음 배우는 사람, 학생(Maya 무료 교육판이 있음), Maya 파일·MEL 호환을 원하는 사람, 3ds Max 사용자.

## 3. "성공"의 정의 — 대상 사용자가 이렇게 말하면 성공
1. **"설치하고 첫 1시간 안에 막히지 않고 내 작업을 했다."** (모델 → UV → 머티리얼 → 렌더, 또는 리그 → 간단한 애니 → 렌더)
2. **"내가 만든 파일이 Maya에서도 그대로 열린다."** (P2: 회사와 집을 오갈 때 축·스케일·리그가 깨지지 않음)
3. **"2주 뒤에도 Maya 모드를 켜 두고 쓴다."** (일회성 구경이 아니라 실제 도구)
4. **"Blender로 온 이유(렌더·무료)를 바로 누린다."** (Maya 습관 때문에 Blender 장점을 못 쓰는 일이 없음)

## 5. 원칙 — 무엇을 Maya로, 무엇을 Blender로
| 판정 | 범위 |
|---|---|
| **Maya 그대로** | 손 습관(내비게이션, 선택, QWERTY, 핫박스, 마킹메뉴, 홀드 키, Channel Box), 조용히 틀어지면 안 되는 것(단위 cm, 부모 지정, Freeze, 내보내기 축·스케일·리그) |
| **Maya 자리에 Blender 기능** | 렌더·셰이더·Geometry Nodes·스컬프트·시뮬레이션은 Blender 기능을 Maya 메뉴 자리에서 열고 Maya 말로 설명 |
| **안내만** | Y-up과 Z-up 차이처럼 바꿀 수 없는 것은 숨기지 않고 알려 준다 |
| **하지 않음** | .ma/.mb 읽기, MEL, Y-up 월드, maya.cmds 확장, 메뉴 개수 늘리기 자체를 목표로 삼는 것 |

## 6. 지금 방향 (결정됨)
- **멈춤:** 새 Maya 메뉴·편집기 늘리기. 버그 수정과 "첫 1시간" 문제만.
- **1순위:** 리그 FBX를 Maya로 보낼 때 깨지는 문제 + Y-up 차이 안내.
- **언어:** 영어만 (일본어 입구 만들지 않음).
- **태그라인:** 현행 유지 "The whole Maya workflow in Blender, in one install".
- **사용자에게 묻기:** 영어 설문 + GitHub 이슈 + 앱 안 피드백 링크.

## 7. 아직 확실하지 않은 것 (목표를 흔들 수 있는 것)
1. **태그라인과 원칙의 충돌.** 원칙은 "Maya 전체 복제가 아니다"인데, 태그라인은 "the whole Maya workflow"를 약속한다. 실제 외부 평가(BlenderArtists)도 "D 피벗이 다르다, Quad Draw가 다르다"처럼 *전부* 기준으로 평가했다. 유지하려면 "whole"이 무엇을 뜻하는지(손 습관 전체? 메뉴 전체?) 정해 둘 필요가 있다.
2. **영어만 vs 실제 도달.** 지금까지 반응의 87 %가 일본어 게시물에서 왔다. 영어만 유지해도 되지만, 설문 응답이 영어권에서만 오면 가장 큰 관심층의 목소리를 놓친다. (설문 문항만 일본어로 두는 정도는 "UI 번역"과 다른 결정)
3. **"첫 1시간" 시나리오를 누구 기준으로 할지.** 모델러 흐름과 애니메이터 흐름 중 무엇을 기준선으로 삼을지. 1순위를 리그 FBX로 정한 것은 P2 애니메이터 쪽을 가리킨다.
4. **6개월 뒤 목표 숫자.** North Star를 "줄지 않음"으로 둘지, 구체적 숫자(예: 릴리스당 14일 다운로드 1,000)를 둘지.
5. **언제 다시 기능을 늘릴지.** "설문 결과가 나오면"의 기준: 응답 몇 개, 기간 몇 주.
